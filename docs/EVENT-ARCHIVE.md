# Portable Event Archive (T4C)

Organizer export is `GET /events/:eventId/archive`. Any authenticated user who can create an event can preview and confirm an archive at `POST /events/archives/preview` and `POST /events/archives/confirm`. The organizer interface is at `/events/archive` and in event management. Import is explicit; Docker startup and the official fixture loader do not invoke it.

The UTF-8 JSON package has `format: "dogfood-event-archive"`, `schemaVersion: 1`, source instance and event UUIDs, `exportedAt`, a manifest of per-collection counts and total rows, payload, and a SHA-256 `packageHash`. The hash covers every field except itself. Canonical serialization sorts object keys recursively, preserves array order, and uses JSON string/number encoding. Export sorts collections by stable identity. Schema version 1 rejects unknown fields, unsupported versions, bad counts/hash/references, unsafe object keys, objects over 40 levels deep, uploads over 20 MiB, collections over 10,000 rows, and packages over 50,000 rows. Future format changes require a new version and explicit compatibility handling; v1 import does not guess how to interpret future packages.

The archive includes the event, memberships, tracks, prizes, registrations, teams, projects, submissions, judge profiles and conflicts, rubric/assignment/evaluation state, scoring and results, signed judge records with public verification keys and rotation data, webhook endpoint configuration, aggregate vote counts, and organizer-owned private project comments. The field allowlists are in `apps/api/src/modules/event-archive/archive-format.ts`. It excludes sessions, password and credential hashes, tokens, voter identities and individual ballots, webhook secrets and delivery queues, signing private keys, security internals, and audit history. Comments can contain sensitive organizer evidence; protect the downloaded file accordingly. Comment authors become deactivated placeholders. Aggregate votes preserve totals but cannot reconstruct ballots, deduplicate past voters, or re-establish historical voter identity.

Source users are never merged by email. Each receives a deterministic new UUID and a deactivated, unverified, unclaimed `@archive.invalid` account with a null password hash. Database checks prevent sessions, platform roles, and authentication on placeholders. The importing account becomes organizer of a **new** event; the source relationships remain attached to placeholders. Preview displays the source, counts, placeholder mappings, ID remapping, warnings, privacy consequences, and exact package hash. It writes only preview and safe audit metadata, never event-domain data. Confirm requires the same authenticated actor, an unexpired preview, and the same package hash. A changed package needs another preview. Exact source instance/event/hash repeats return the prior destination. A changed archive has a new hash and creates a distinct import version after preview.

Import runs in one database transaction with existing foreign keys, checks, and immutability triggers enabled. A failure rolls back users, event, domain rows, provenance, and audit. The destination event always starts `DRAFT`, `PRIVATE`, with a hidden gallery, regardless of source publication. Source domain dates are retained where valid; import operational timestamps are new. Rubrics, runs, and evaluations pass through their normal transition states so existing guards continue to apply. Completed ScoreRun source input hashes are checked against sorted submitted evaluation IDs; destination hashes are recomputed from the remapped IDs, while source hash and ID remain in the archive/provenance. Result snapshots are retained. Semantic round-trip normalization reverses ID remapping and accounts only for the importing organizer, destination publication state, webhook disablement, source-signature provenance, signing-key lifecycle, and remapped ScoreRun hash.

Webhook URLs and event types are portable, but imported subscriptions are disabled and contain no secret. An organizer must explicitly configure a new destination secret before activation. Import actions are not webhook event types and create no outbound delivery. Historical signed judge records retain their canonical payload, signature, issuer key ID, public verification material, and revocation history. They are never signed with the destination private key. API and certificate display source-issued provenance separately from destination-issued records. A public key already present in the destination is reused only if its fingerprint and material match.

To migrate, export as organizer, safeguard the JSON file, open `/events/archive` on the destination, select it, inspect the preview/hash and identity/privacy warnings, then explicitly confirm. Inspect the new private draft event before publishing or re-enabling webhook subscriptions. `npm run test:t4c` exercises validation and an import/export semantic round trip against an isolated `_test` database. The official fixture can be imported into that isolated database, exported, imported as a new event, and compared with `semanticNormalize` from `archive-normalize.ts`.
